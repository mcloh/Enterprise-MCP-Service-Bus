# Enterprise MCP Service Bus — Reference Implementation

Executable implementation of the architecture described in [`../README.md`](../README.md)
(reference architecture). For the complete technical reference of what exists and how it works,
see [`docs/AS-BUILT.md`](docs/AS-BUILT.md).

## Status

The entire planned backlog (milestones M0 through M4) is implemented, tested, and validated.
**261 automated tests**: 254 pass with `pytest --forked` (unit + e2e + contract + adversarial),
plus 7 security acceptance tests (`tests/e2e/test_security_acceptance.py`) that require real
Docker and are run separately due to the build+Keycloak cost per run. Production logic with no
mocks in the security and orchestration core: real OPA (subprocess), real Keycloak (Docker),
real LangGraph with a SQLite checkpointer, a real LLM (OpenAI-compatible endpoint), real HTTP
JWKS with real RS256 JWTs, real YAML from `config/`, real SQLite for the Registry.

## Quickstart (without Docker)

```bash
make install         # creates .venv and installs the package in editable mode (dev extras included)
make lint             # ruff check + ruff format --check
make typecheck        # mypy --strict
make validate-schemas # validates all YAML under config/ against its Pydantic model
make test             # pytest --forked (unit + e2e + contract + adversarial)
```

`make test` needs the `opa` binary on the PATH (or `OPA_BINARY`) for the tests that exercise the
real PDP — without it, those tests are skipped (`pytest.skip`), not failed. `docker` on the PATH
is required for the same reason for `tests/e2e/test_real_keycloak.py`. See
[`docs/How-To.md`](docs/How-To.md) for the complete step-by-step, including how to install OPA
without Docker and bring up the services directly on the host.

## Quickstart (Docker)

```bash
make up      # == docker compose --profile core up --build   (without IdP)
make down
make logs

# With a real Keycloak:
cp .env.example .env   # uncomment the 3 OIDC_* lines
docker compose --profile core --profile identity up --build
```

See [`docs/How-To.md`](docs/How-To.md#bringing-up-the-local-stack) for the available profiles
(`core`, `identity`, `observability`) and what each one adds.
